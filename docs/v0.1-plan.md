# v0.1 execution plan

ShuhaFFT v0.1 is a correctness release for one transform family: CPU
complex-to-complex radix-2 FFTs over `Float32` and `Float64` components.
Performance work starts only after this contract is complete.

## Current status

The first working slice completes the semantic foundation and scalar radix-2
kernel. It includes a four-point hand reference, an eight-point shifted-impulse
reference, cross-precision origin-delta and constant references, `Float32`
complex round trips, `Float64` Parseval coverage, singleton behavior, and
validation failures. Remaining v0.1 work is broader numerical confidence,
installed-package verification on every supported target, API review, and
release documentation. No performance milestone has started.

## Public contract

- `FFTDirection` distinguishes the forward transform, whose exponential has a
  negative sign, from the inverse transform, whose exponential has a positive
  sign.
- `FFTNormalization` supports unscaled, backward, forward, and orthonormal
  conventions. Backward normalization is the default: the forward transform
  is unscaled and the inverse is divided by the transform length. Its two-Bool
  representation makes all externally constructible or mutated states valid.
- `FFTPlan[dtype]` validates a non-zero power-of-two length once and owns the
  transform semantics. Execution revalidates reachable plan state and rejects
  data whose length differs from the plan.
- `execute()` preserves its input and returns a new `List`.
- `execute_in_place()` mutates the provided `List` without changing its length.
- v0.1 supports only `DType.float32` and `DType.float64` complex scalars.

## Milestone 1 — semantic foundation

Deliverables:

- nominal direction and normalization values;
- plan construction and power-of-two validation;
- deterministic normalization-factor tests;
- explicit errors for zero, non-power-of-two, and mismatched lengths.

Exit criterion: semantic tests pass with the pinned Mojo compiler.

## Milestone 2 — scalar radix-2 kernel

Deliverables:

- iterative bit-reversal permutation;
- iterative decimation-in-time butterflies;
- `Float32` and `Float64` specializations through one typed implementation;
- forward/inverse and in-place/out-of-place execution through `FFTPlan`.

Exit criterion: delta, constant, impulse-shift, and hand-computed four-point
reference transforms pass.

Status: complete for both supported precisions. Delta fixtures also cover the
inverse dual, reusable-plan determinism, input preservation, and independent
out-of-place result ownership.

## Milestone 3 — numerical confidence

Deliverables:

- forward/inverse round-trip invariants for real and complex fixtures;
- Parseval energy checks under backward normalization;
- cross-precision fixtures and documented tolerances;
- empty, singleton, and length-mismatch boundary tests.

Initial tolerances are `1e-5` absolute/relative for `Float32` and `1e-12`
absolute/relative for `Float64`. Any relaxation requires a fixture and an
explanation in the test.

Exit criterion: `pixi run check` and the public example pass on the supported
CI matrix. `pixi run package` exercises the installed-package smoke test locally
and in the tag-triggered release workflow.

## Milestone 4 — release readiness

Deliverables:

- document every public symbol and failure mode;
- replace the scaffold README example with the real API;
- record benchmark methodology without performance claims;
- verify the package recipe exports exactly the documented root API.
- keep installed-package verification as a release gate on every supported
  target, separate from the faster push and pull-request CI lane.

Exit criterion: v0.1 can be consumed without importing an internal module.

## Deferred seams

The plan is the stable semantic seam. Later CPU implementations, precomputed
twiddles, SIMD kernels, mixed-radix algorithms, and GPU backends must implement
the same direction and normalization behavior behind it. v0.1 does not expose
backend selection, real transforms, multidimensional transforms, batching,
SIMD, GPU, mixed radix, or Bluestein.
